# Why this repository exists

## Why notes are private

My private notes can contain rough thinking, unfinished ideas, mistakes, and personal information. They are useful while learning but are not evidence that another person can review or run.

## Why docs are public

The `docs/` folder contains the decisions, explanations, results, and lessons that support the code. A reviewer should be able to understand what I built, why I chose it, and what I learned.

## What a hiring reviewer sees first

In the first 30 seconds, a reviewer should see:

1. The target role: Azure Data Engineer.
2. A short explanation of the project.
3. Eight planned artifacts that show the scope of the work.
4. A clean folder structure for SQL, Python code, pipelines, notebooks, documentation, and tests.

The goal is to make the project understandable before the reviewer reads any detailed code.
